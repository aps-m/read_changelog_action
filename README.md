# read_changelog_action

Действие для вывода информации по указанному релизу из указанного файла
changelog.

## Применение

Автоматизация публикации изменений по релизу

## Маркировка релизов

Пример обозначения предварительного релиза

```md
## 0.0.2-b2
```

Пример обозначения финального релиза

```md
## 0.0.3
```

## Параметры

### Вход

| Параметр | Описание            | Тип    | Обязательный | Значение по умолчанию |
| -------- | ------------------- | ------ | ------------ | --------------------- |
| filename | Changelog файл      | Строка | Да           | none                  |
| tag      | Запрашиваемый релиз | Строка | Да           | none                  |

#### Примечание

Параметр tag ищется по совпадению, таким образом запросив релиз без окончания
-b\* (Например 0.0.1), результат покажет изменения по всем предварительным
релизам, название которых начинается с входного параметра tag.

### Выход

| Параметр | Описание                   | Тип    |
| -------- | -------------------------- | ------ |
| content  | Список изменений по релизу | Строка |

### Ссылки на задачи

В выбранном блоке changelog поддерживаются три формата ссылок на задачи:

- `(#число)` — задача в текущем репозитории организации `APS_Soft`.
- `(repo#число)` — задача в указанном репозитории организации `APS_Soft`.
- `(org/repo#число)` — задача в указанной организации и репозитории.

Записи преобразуются в Markdown-ссылки с текстом `#число` на
`https://git.aps-m.com/<организация>/<репозиторий>/issues/<число>`. Имя текущего
репозитория берётся из переменной окружения `GITHUB_REPOSITORY`
(`владелец/репозиторий`), которую задаёт runner. Если переменная отсутствует или
имя репозитория пустое, записи `(#число)` остаются без изменений, а ссылки с
явно указанным репозиторием преобразуются. В именах организации и репозитория
поддерживаются латинские буквы, цифры, `_`, `-` и `.`. Круглые скобки остаются
обычным текстом за пределами ссылки.

Например, для репозитория `mir` строка `Тест (#35).` преобразуется в:

```text
Тест ([#35](https://git.aps-m.com/APS_Soft/mir/issues/35)).
```

Записи `(other_repo#35)` и `(other_org/other_repo#7)` преобразуются в:

```text
([#35](https://git.aps-m.com/APS_Soft/other_repo/issues/35))
([#7](https://git.aps-m.com/other_org/other_repo/issues/7))
```

При прямой отправке результата через Telegram Bot API используйте
`parse_mode: Markdown`, чтобы кликабельным был текст `#35`. Экшен возвращает
Markdown, но сам не отправляет сообщение и не задаёт режим разметки Telegram.
Для `MarkdownV2` требуется дополнительное экранирование специальных символов во
всём сообщении; для `HTML` — преобразование Markdown в HTML на стороне
отправителя. Подробнее:
[форматирование Telegram Bot API](https://core.telegram.org/bots/api#formatting-options).

В шаге `aps-m/telegram-notify-action` явно укажите `parse_mode: Markdown` (по
умолчанию этот экшен использует `HTML`). Параметры текста и разметки:

```yml
with:
  # Существующие параметры token и to сохраняются.
  message: ${{ steps.changelog_action.outputs.content }}
  parse_mode: Markdown
```

## Пример использования

### Пример файла

changelog_examples/changelog.md

```md
## 0.0.2-b2

- change 1.1;
- change 2.1;
- change 3.1;

## 0.0.2-b1

- change 1.2;
- change 2.2;
- change 3.2;

## 0.0.1

- change 1.3;
- change 2.3;
- change 3.3;
```

### Использование действия

```yml
- name: test changelog reading
  id: changelog_action
  uses: aps-m/read_changelog_action@v5
  with:
    changelogfile: 'changelog_examples/changelog.md'
    tag: '0.0.1'
```

### Пример использования результата

```yml
- name: Test changelog action result
  run: echo "${{ steps.changelog_action.outputs.content }}"
```

Результат выполнения команды:

```
* change 1.3;

* change 2.3;

* change 3.3;
```
